# AI辅助投稿：架构与安全边界

## 用户流程

1. 登录后选择网址或文章，新投稿接口与网页智能读取接口同步只接受这两种类型；历史其他类型仍可查看和审核。
2. 网址先填写公开网页地址，可直接手工完善；文章先填写标题与正文，摘要和参考网址选填，不要求网页采集。
3. 分类从同类型一级分类逐级选择，显示完整路径；更换上级清空下级，同名分类按 ID 区分。服务端拒绝隐藏祖先、失效、跨类型或循环路径。
4. 选择智能读取时，服务端执行 URL、DNS、重定向、响应类型、大小和超时检查，提取标题、描述、站点名和正文摘要。
5. 若存在已测试并启用的 OpenAI 兼容服务，则生成标题、简介、说明、标签与分类建议；分类候选提供完整可见路径。
6. 自动读取与“采用全部可用建议”只补全空白项；单项“采用建议”明确替换对应字段。网页地址变化清除旧快照、建议、重复提示和自动图标，保留手工输入及手工图标。
7. 当前页面内切换网址和文章分别保留草稿与 AI 证据；读取、图标保存及提交期间限制切换和重复操作。刷新页面不承诺恢复草稿。
8. 投稿保存用户最终值、网页快照和 AI 候选值，等待管理员审核。失败保留输入并标记字段；禁用 JavaScript 时可使用同样服务端校验的原生表单，成功跳转投稿记录。
9. 重复提示只展示已发布、公开内容标题；其他待处理投稿仅展示数量。管理员对比三方证据，选择正式分类和已有标签后发布或拒绝。

## OpenAI兼容服务

- 调用`POST {baseUrl}/chat/completions`。
- 默认使用`response_format={"type":"json_object"}`；服务返回400/422时自动降级为普通Chat Completions并继续解析严格JSON。
- 输出字段有服务端长度、数量和类型限制。
- 配置修改Base URL、模型或API Key后会自动停用并清除测试状态。
- 服务必须通过真实连接和结构化输出测试后，管理员才能显式启用。

## 密钥保护

- D1仅保存AES-GCM密文、随机IV和末4位提示。
- 32字节加密主密钥位于Cloudflare Secret `AI_CONFIG_ENCRYPTION_KEY`。
- 后台Loader、表单和API不回传密文或明文Key。
- 编辑配置时API Key留空表示保留；修改Key会重新加密并要求重新测试。
- 生产备份只记录Secret名称，不记录主密钥值。

## 网页抓取和SSRF

纯Cloudflare Worker无法将任意第三方域名的HTTP连接固定到预解析IP，因此当前方案是折中防护，不能完全消除DNS rebinding/TOCTOU理论风险。

当前防护：

- 仅HTTP/HTTPS和标准80/443端口；
- 拒绝URL凭据、localhost、私网、链路本地、保留和特殊用途IPv4/IPv6；
- 通过DNS-over-HTTPS检查全部A/AAAA结果；
- 每个重定向目标重新执行同样检查；
- 手工重定向，限制跳转次数；
- 仅接收HTML/XHTML；
- 读取字节、提取正文和请求时间均有限制；
- 不转发用户Cookie、Authorization或浏览器请求头；
- 自定义AI Base URL在实际出站前也执行公网DNS检查。

如果未来Worker接入私网Service Binding/VPC、处理高敏感数据，或需要严格消除DNS重绑定，应把抓取迁移到具备DNS解析结果固定、出站ACL和网络隔离的独立Fetcher服务。

## Prompt Injection边界

- 网页正文永远作为`<untrusted_webpage>`不可信数据传给模型。
- 系统消息明确禁止执行网页中的指令。
- AI无工具调用、无数据库访问、无Cloudflare凭据，也不能直接发布内容。
- 模型输出只按白名单JSON解析；Markdown围栏可剥离，其他自由文本或缺字段结果拒绝。
- AI结果必须由用户确认并经过管理员审核。

## 限流和审计

- 同一用户两次智能获取至少间隔5秒；
- 每个用户每10分钟最多10次；
- D1仅记录用户ID、动作、Provider ID、成功状态和错误类型；
- 不记录API Key、网页正文、模型完整响应或Authorization头。

## 降级策略

- 未配置AI时仍返回网页原始标题、描述和正文摘要；
- AI故障不会阻止用户手动投稿；
- 抓取失败时表单保留手动填写能力；
- 审核发布继续使用现有服务端分类、标签、Slug、媒体和关系校验。

## 迁移与初始数据

- `migrations/`只允许`NNNN_name.sql`编号迁移，Wrangler会把目录中的每个SQL视为生产迁移。
- 初始演示数据位于`seeds/initial.sql`，只能在新建空数据库时显式执行，不能随生产迁移自动运行。
- 备份会同时收录编号迁移和Seed，但两者在Manifest中使用不同目录。

## AI 服务管理与调用诊断（2026-10-17）

后台入口为 `/admin/ai-providers`。

1. **配置**：基础配置填写名称、API 根地址、模型与密钥；高级参数折叠展示请求超时、正文上限与系统提示词。顶部“当前实际使用”取服务器启用状态，不把正在编辑或刚测试通过的服务当成正在使用。
2. **保存**：保存后留在对应编辑器。页面列出尚未保存的字段；只修改名称保留测试与启用状态，修改地址、模型、密钥、超时、正文上限或提示词会停用该服务并要求重新测试。不会自动启用备用服务。
3. **测试**：仅测试已保存配置。当前编辑器有未保存修改时，需先保存才能测试或启用该项。区分地址/模型、密钥/权限、超时、网络、返回格式、限流和上游错误，并提供下一步建议。测试不会刷新整个页面或自动启用；测试失败沿用停用该服务的规则。配置在测试期间变化时，迟到结果不得改变新配置的测试状态。
4. **启用**：通过测试后显式启用，单条数据库语句完成切换；目标配置变化导致切换失败时保留原启用项。名称修改不触发连接测试，其他运行参数改变须重新测试。
5. **失败保留输入**：JavaScript 增强表单保存失败保留本页所有输入，包括尚未保存的密钥；服务器响应不回传密钥。刷新页面后未保存密钥不恢复。无 JavaScript 可使用原生保存、测试与启用流程，保存失败保留非密钥字段，密钥需重新输入。
6. **调用记录**：`?tab=history` 按来源（连接测试/投稿智能读取）、结果（成功/失败/未调用 AI）、服务筛选，每页 20 条，URL 保留筛选与页码，统一北京时间。桌面使用表格，手机使用逐条记录卡片，无需横向滚动查看失败原因。记录服务/模型快照、失败阶段、安全错误分类、总耗时及 AI 耗时；未启用 AI 的网页抓取标记为“未调用 AI”，网页读取失败不冒充模型调用失败。删除服务后历史名称与模型保留。

调用记录不保存密钥、Authorization、网页 URL/正文、系统提示词或上游完整响应。记录写入失败不把成功的生成改判为失败；连接测试会提示记录保存异常。筛选页面读库失败明确提示，不能显示成零条结果。旧 `ai_usage_events` 继续承担限流及预占管理；新诊断记录从本次迁移后开始，不为旧事件编造耗时。进程意外终止可能没有完成记录，不能把这份诊断列表视为完整计费账本。

这里的“成功”表示服务端已返回可用建议，不代表浏览器已经采用或发布。投稿页会自动补全空白项；已有内容需手动采用建议才会替换。**后台内容编辑中的“网页信息读取”仅抓取网页，不调用 AI**，不应在 AI 调用列表里寻找这类操作。

### 本轮迁移与发布

新增 `migrations/0021_ai_service_calls.sql`，建立独立诊断表及索引，不修改已有配置、密钥或限流事件。部署前在正确的 Cloudflare 账号与项目中应用待执行的编号迁移：

```bash
npx wrangler d1 migrations list navinest --remote
npx wrangler d1 migrations apply navinest --remote
```

这是正式数据库操作；本轮开发和浏览器验证只使用隔离的本地 D1，不自动执行正式迁移或发送正式 AI 请求。迁移未应用时配置页继续可用，但调用记录页会提示不可用，新记录无法保存。绑定、依赖、Cron 与自定义 Worker 入口保持原样。
