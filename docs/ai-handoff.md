## 本轮已完成：P0 + P1 + P2（原始要求与验收依据）

### P0：修正右侧排行榜条目跳转

**实施前代码事实：** `src/routes/+page.svelte` 右侧“排行榜”循环展示 `data.dashboard.popular`，但每个标题都链接到 `/rankings`。用户点击某条内容标题，打开的是排行榜总页。

实施要求：

- 条目标题进入该条内容的站内详情，只有区块“更多”链接进入 `/rankings`。
- 使用条目的真实 `type` 与 `slug`，覆盖网址、文章、软件、书籍和公告五种类型。
- 复用或提取共享详情路由映射，供卡片和排行共同使用，避免复制后两处规则不一致。
- 保留原生 `<a>` 链接、键盘操作与浏览器打开新标签页的能力。
- 不以裸外链替代详情页，不绕过 `/go` 的安全校验。
- 如果 P1 最终移除了右侧排行，检查其余所有排行标题入口；确保同类问题不会留在主内容区或排行页。

| 内容类型   | 标题目标            |
| ---------- | ------------------- |
| `site`     | `/sites/[slug]`     |
| `post`     | `/posts/[slug]`     |
| `app`      | `/apps/[slug]`      |
| `book`     | `/books/[slug]`     |
| `bulletin` | `/bulletins/[slug]` |

验收：用不同类型、不同 slug 的条目实际点击检查 URL 与目标内容；区块“更多”仍进入总排行；访问箭头仍走安全外链入口。

### P1：整理首页内容顺序，减少重复

**实施前代码事实：** 主区块可以展示排行榜、分类、热点等模块；右侧栏固定展示站点信息、今日热榜、排行榜。首页可能出现重复排行/热点。模块启用与顺序已有后台配置，实际呈现需结合数据库配置判断。

建议方案：

- 默认浏览顺序优先体现“搜索 → 常用推荐/分类资源 → 辅助排行与资讯”，让网址导航的核心内容更早出现。
- 主内容与右侧栏保留一处主要排行榜，避免重复展示相同榜单。优先考虑去除右侧重复排行，并保留主排行及独立排行页；若选择其他方案，在 PR 中说明阅读路径。
- 热点同样检查重复，可在侧栏保留少量摘要、独立页面保留完整列表，避免两处同时铺开相同内容。
- 混合内容明确标识“网址、软件、文章、书籍、公告”。不要因为文章或公告分数高就认为排行算法存在缺陷，也不要未经分析改变评分规则。
- 将 `more+` 等入口文案统一为“更多”或“查看全部”。
- 内容稀疏时保持正常卡片宽度，不让单条网站卡片撑满整行；空分类说明情况并提供可用下一步。

实施边界：继续使用现有 `modulePlan` 的启用、配置与排序能力。调整默认配置时，不强制覆盖管理员已经保存的顺序，不修改生产 D1 数据来制造演示效果。需要运营调整配置时，写明具体建议和步骤。

验收：无重复的主要榜单；分类和常用资源更易找到；禁用模块不被重新显示；导航目录顺序、锚点和滚动高亮与最终模块顺序一致；少量内容、大量内容、空分类均无明显空洞或溢出。

### P2：卡片直接说明用途

**实施前代码事实：** 卡片已有 `summary` 数据和简介节点，但首页网站/软件卡片的部分旧样式隐藏了简介，用户主要看到标题与浏览/收藏统计。完整信息主要依赖悬停提示或详情页。

实施要求：

- 首页网址/软件卡片显示一行简短用途，窄屏可在保证布局稳定的前提下适当换行；长文本正常截断。
- 顺序体现“标题 → 用途 → 次要信息”。浏览与收藏统计弱化，不能挤占标题或简介空间。
- 类型标识保持可辨识；域名可作为有帮助的次要信息，但只从已有有效 URL 提取，不新增不必要的抓取请求。
- 空简介不编造文案，也不保留多余空行；必要时显示已有域名或类型。
- 保留完整标题/简介提示与手机详情入口，手机操作不能依赖 hover。
- 保留现有字号、字重、主题对比度和 44px 主要触控区域，不能为了塞更多列缩小文字。
- 公共组件的修改同步检查搜索结果、分类、标签与详情等页面，避免仅首页好看而其他页面回退。

验收：无需悬停即可判断网站用途；中文长标题、长英文单词、空简介、无图标、大统计数值均可读；统计不重叠、不异常换行；标题和外链两个入口仍清晰且独立。

## 本轮实现与运营配置说明

- 新 seed 和本地 fallback 的排行榜默认排序为 `100`。未配置的分类补在末尾辅助榜单之前；显式保存模块的相对顺序保持不变。禁用内容模块对应的分类不再被自动补齐，若另有同分类启用模块，则按启用配置显示。目录由最终 `modulePlan` 生成，定位与高亮规则沿用原实现。
- 2026-10-11 只读正式首页核对显示：主排行榜在常用推荐之前，右侧同时有热榜和排行榜。本轮没有修改正式 D1。**希望现有站点采用推荐优先顺序时**，请在后台“首页模块”把“排行榜”排序从 `15` 调至 `100`，保留“聚合搜索”`10`、“常用推荐”`20`、“开发工具”`30`，保存后分类会自动出现在末尾排行之前。需要首页热点时，再使用已有热点模块开关并将其排序置于排行之后（例如 `110`）；不需要时保持禁用。不要重跑历史 `0010` 排序迁移覆盖管理员选择，也不要为展示运行全量 seed。
- 首页网站/软件及紧凑排行卡片显示一行用途；公共结果卡片最多两行。旧隐藏规则通过公共简介选择器修正，不改变字号/字重令牌。类型放在标题/用途之后；统计为 13px 辅助文字，万/亿紧凑显示，完整值保留在提示中。空简介及空提示行不渲染。
- 首页网格沿用 260px 最小卡片宽度，改用 `auto-fill` 保持稀疏列宽；小屏仍使用可用宽度。空分类、空排行和空热点有说明及可操作入口。

## 后续阶段：P3 搜索与筛选

本阶段记录为后续规划，不与前三项强行捆绑。

当前站内搜索页面主要使用 `q` 参数，没有类型/分类筛选界面；首页推荐关键词是固定字符串，点击后交给当前选中的搜索引擎处理，不是实时热度数据。

建议：

1. 站内搜索增加内容类型与分类筛选，筛选条件写入 URL，刷新及前进/后退可恢复；组合筛选按交集执行，结果数量与空状态同步更新。
2. 后续可增加匹配词高亮与更合理的相关度排序。先检查 `items.ts` 的实际检索规则，再决定实现；不能只凭界面推断数据库查询能力。
3. 记住用户选择的搜索引擎；存储访问失败或引擎已删除/停用时回退到有效默认值，不能导致页面报错。
4. 把固定“热门”改为“推荐搜索”；如实现后台配置，复用现有配置体系并补充校验、默认值和迁移兼容，不虚构搜索热度。
5. 明确当前是站内检索还是外部引擎搜索，推荐词点击行为与选中引擎一致。
6. 分类子标签可考虑通过 URL 记住筛选状态，并完善键盘操作；不要重新引入分类点击与定位不一致的问题。
