# NaviNest 公共界面规范

参考 [形色场 UI Handbook](https://zzhzhouzhou.github.io/UI-handbook/)，结合网址导航的内容密度制定。本文是项目内的具体约定，后续公共页面与组件沿用这些规则。

## 视觉基础

颜色、间距、圆角、控件高度、动画和层级由 `src/routes/design-tokens.css` 管理；公共组件样式由 `src/routes/ui-foundation.css` 管理。既有 `--nav-*` 变量映射到同一套令牌。

| 项目 | 约定                                                                                        |
| ---- | ------------------------------------------------------------------------------------------- |
| 颜色 | 中性背景与卡片；红色用于品牌、当前入口、主要操作；成功与错误同时提供文字或图标              |
| 文字 | 辅助 12px、常规 14px、区块约 18–20px、页面 32px；中文系统字体优先；标题和内容允许按密度调整 |
| 间距 | 使用 4 / 8 / 12 / 16 / 24 / 32px；先保证标题阅读空间，再决定列数                            |
| 圆角 | 小控件 6px，卡片 12px，覆盖层 16px                                                          |
| 触控 | 主要操作与手机入口使用至少 44px 的可点区域；不靠缩小点击范围提高密度                        |
| 层级 | 普通内容 0，悬浮信息 10，固定头部 40，底栏 45，遮罩 50，抽屉 51，提示 60，跳转入口 70       |
| 深色 | 替换语义令牌；背景、正文、辅助文字、输入框、抽屉和提示均单独检查                            |
| 动效 | 小反馈约 150ms，覆盖层约 220ms；尊重减少动态效果偏好                                        |

正文与辅助文字的目标对比度为 4.5:1，控件边界与焦点清晰可辨。具体的卡片颜色属于内容标识，避免把所有内容类型做成大面积彩色背景。

## 组件交互

- 标题链接进入内容详情；访问箭头经过安全跳转页，在新标签页打开。二者保持独立链接，支持浏览器原生键盘和新标签页操作。
- 紧凑卡片在悬停或标题获得键盘焦点时，显示完整标题、简介与操作说明。手机端保留访问入口与足够的点击范围。
- 首页与结果页使用同一个搜索表单。空关键词不能提交；输入后可以清空并恢复输入焦点；搜索期间显示忙碌状态。
- `/` 或 `Ctrl / ⌘ K` 聚焦当前搜索框。在输入、选择、富文本编辑或模态菜单中，不抢占键盘输入。
- 搜索引擎使用带按下状态的按钮组。分类页内标签保留各自筛选逻辑，导航定位规则沿用现有回归检查。
- 手机抽屉打开后焦点进入关闭按钮，背景不可聚焦；Tab 与 Shift+Tab 在抽屉内循环。Escape、关闭按钮或遮罩关闭后恢复触发按钮焦点；切回桌面宽度自动关闭。
- 普通与成功提示默认短暂展示；错误默认保留到手动关闭。所有提示都使用明确的关闭按钮，成功与错误分别通过状态和警报区域反馈。
- 空列表解释当前情况并提供返回首页或浏览分类的下一步；网络导航继续使用全局加载反馈。

## 验证

`npm run test:home-layout` 覆盖分类锚点定位、首页 12 种布局，以及首页、搜索结果、空结果和详情页的 24 种浅色/深色布局与手机焦点控制。新增组件继续检查 320px 宽度下无水平溢出、可见键盘焦点、搜索行为与主题对比度。

本轮完善现有公共页面与交互。高级命令面板、粒子背景、复杂转场等，按具体使用场景单独设计。
